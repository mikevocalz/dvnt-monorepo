# Watch v2 message and Wear implementation evidence

Date: 2026-09-05. This slice is source implementation and local verification, not a release or paired-device sign-off.

## Reproduced findings

- **D:** `send-message/index.ts` previously inserted every delivery. `messages.operation_id` now has a sender-scoped unique index. The winning insert alone reaches read effects and push; conflict recovery returns the existing row, rejects a changed body/metadata/conversation, and never repeats notifications. The UUID remains nullable for existing phone clients. Watch transport acknowledgment is not send confirmation.
- **E:** `messagesApi.getConversations` discarded `_rawTs` after formatting. The existing display `timestamp` remains; `createdAt`, `lastMessageId`, `lastSenderId`, and actual `lastMessageMetadata` are additive. Strict watch reads propagate auth/query/category/block failures instead of manufacturing an empty inbox.
- **G:** Existing `getMessages` queries ascending plus limit. Its callers remain intact; `getThreadPage` uses descending `created_at,id`, a bounded 25-message page (maximum 30), one-row lookahead, and a stable older cursor before reversing for display. Microsecond timestamp strings are preserved.
- **P:** `realtime.ts` originally only provided safe channel creation. The actual INSERT-only subscribers were in message screens. `bindMessageChanges` adds message `*` and viewer `conversation_reads` subscriptions before subscribing; the new migration publishes read cursors. The watch sync integration owns calling the helper.

Further confirmed: `react-message` previously checked neither conversation membership nor blocks and used a read/modify/write metadata race. The service-only `set_message_reaction` RPC now locks the message row, validates authenticated membership and bilateral block rules, preserves unrelated metadata, and supports idempotent desired-present updates. Omitted desired state keeps legacy toggle semantics. The allowed set is 😂 😢 😊 😈 🥵 💝 ❤️.

The four-person call cap had leaked into group-chat creation and native/web selection. Those guards and misleading copy were removed. Minimum two selected people and group-name validation remain. The native group screen now uses the existing Zustand store.

## Wear source implementation

- Phone config plugin installs the previously missing `PhoneWearListenerService` manifest entry and keeps source copying/registration idempotent.
- `DVNTWearBridge.syncContext`, `sendResponse`, and `DVNTWearMessage` carry credential-free snapshots/commands. Existing `syncTickets` now resolves on DataClient success instead of before its asynchronous result.
- `broadcastEvent(payloadJson)` sends live MessageClient events only to reachable nodes advertising the DVNT Wear capability, with no replicated fallback for ringing.
- Watch uses replicated `/dvnt/context` plus `/dvnt/command/<requestUUID>` and `/dvnt/response/<requestUUID>`. Requests time out honestly if phone JS is unavailable.
- Native Material 3 Inbox, filters, message pages, bounded image decoding/viewer, RemoteInput, explicit draft/send, durable operation UUID outbox, safe retries, reaction counts/mine and desired-state reaction actions.
- Thread/Inbox list state survives viewer/navigation transitions. New snapshots refresh an open thread; foreground older pages retain their anchor keys and a bounded 250-message window.
- `WearAccountSession` serializes account-scoped ingress across tickets/messages/events, rejects retired generations, and clears tickets, drafts, outbox, thread and image state on account change. Outer context session is accepted before nested domains; versioned legacy `/tickets` delivery uses the same gate.
- AmbientLifecycleObserver removes message/ticket content while wrist-down, showing only a small shifting DVNT mark. Multiple tickets can be selected without changing QR generation.
- Native Calls provide Recents, search, a picker limited to three other people, phone audio/video start, incoming actions, and actual active-call phase/mute/end controls. Expired ringing and missing heartbeats disable controls; this is a phone call companion and carries no native watch audio. Incoming events are not persisted.
- Native Events use real phone snapshots for sections, flyers, event/local time, RSVP and waitlist actions. Ticket purchase, pending invitation acceptance and offer claims continue on phone. Optional venue weather shows the phone snapshot timestamp and uses no watch location. Pending mutations persist as uncertain after restart and are never automatically replayed.
- Native incoming notifications use a permission-gated high-importance channel, generic private text, immutable account/call/expiry-bound actions and system timeout. After process death an unexpired action can reconstruct only its original command from the PendingIntent; phone confirmation is still required, and it is never queued/replayed automatically. Active phone calls use Wear OngoingActivity with timeout tied to the last heartbeat. Full-screen intents are not used.
- Material 3 ProtoLayout tile has title/main/bottom slots, real cached unread-chat count/event countdown and an exact pass/event navigation target. SHORT_TEXT/LONG_TEXT complication data sources expose counts/countdowns only, with bounded validity. Ingress and account resets request system-managed tile/complication updates.
- Unknown/missing/cancelled Wear ticket statuses now fail closed, so they cannot expose a scannable QR or become the tile's Show pass target.
- Release builds no longer inherit the debug signing configuration; the local release APK is explicitly unsigned.

## Completion pass — durable media, reactions and retained history (2026-09-05)

- Apple `WatchMediaCache` now persists authorized HTTPS image bytes in private, backup-excluded Application Support using hashed account-generation/URL/size keys, a 24 MiB disk limit, 2 MiB transfer limit, 8 MiB decoded-memory limit and two transfers. Files use data protection. Account reset, authorization removal and reconciled message deletion purge both disk and memory; in-flight old-generation downloads cannot repopulate the cache.
- Wear `MessageDiskCache` persists in `noBackupFilesDir`, hashes account-generation/URL keys, caps disk at 24 MiB and individual transfers at 4 MiB, and evicts least-recently-accessed files. Bitmap decode remains sampled to 512 pixels with an 8 MiB memory cache and two transfers. Account/authorization/deletion resets fence downloads and erase both caches, including cold singleton reset.
- Apple persists unresolved desired-state thread actions alongside the account-scoped outbox before relay. Relaunch exposes Retry/Cancel; retries preserve add/remove intent. A pending action cannot be overwritten by another uncertain action. Wear persists up to 50 desired-state reaction operations, preserves identity through explicit retry, exposes pending reactions in the conversation after relaunch, and prevents parallel dispatch of the same intent. Backend confirmation clears the intent; transport receipt alone does not.
- Wear now persists eight recently used conversations with at most 250 messages each, including attachment/reaction metadata and the older cursor. Group messages render the projected sender name.
- Both wrists send their retained message IDs with every thread request. The phone bounds and validates IDs (maximum 250), rechecks authorized conversation membership, queries current message existence, and returns removed IDs. Both native stores remove deleted retained messages even when they are outside the newest page. Recently active phone refreshes also reconcile retained IDs. Query failures preserve cached content and surface retry instead of interpreting an error as deletion.

### Wear ticket completion

`MainActivity.TicketScreen` retains the selected ticket ID across snapshot reorder and uses native M3 `TransformingLazyColumn`/`ScreenScaffold` for pass details and the ticket list. `TicketAccessRing.kt` mirrors Apple time geometry: partial within 24 hours of doors, full when open/admitted/scheduled, dashed and code-hidden when invalid or past the event end. The QR matrix encoder/painter and quiet-zone padding are unchanged; the opaque white plate paints above the decorative ring. A 60-second foreground update refreshes time phase and is cancelled when the composable leaves the screen; ambient rendering continues to hide the whole pass. Resolved membership label and door perks appear only for explicit `isOwner == true`; actual Core/Insider/VIP/Founders Circle labels come from the phone, with no inferred subscription capability. Ticket tier, table, entry window, missing-code recovery and next-pass controls remain separate from the ring's time meaning. New tests cover exact door/end/24-hour boundaries, invalid/scanned states, selected ID reorder/removal and owner/unknown-owner membership gates.

### Ticket parser safety

Apple ticket decoding now defaults absent, unknown or malformed status to `unknown`, with a non-scannable "Status unavailable" presentation; cancelled has its own non-scannable status. Both native QR decoders reject dimensions outside QR versions 1–40 (21–177 modules with four-module steps), wrong packed-hex length, and non-ASCII hexadecimal before allocating modules. Canonical 45×45 matrices still accept exactly 507 hex characters, preserving the final nibble's padding. Wear ownership decoding also requires an actual JSON Boolean; the string `"true"` cannot show membership perks. Standalone Swift `TicketSafetyTests` compiles and passes these fail-closed cases; Wear assertions cover unbounded/invalid dimensions, incomplete/extra/invalid hex and valid canonical size. No matrix encoder or QR quiet-zone renderer was changed.

### Cold-start action and conversation corrections

Cold-start call notification responses now remain unconsumed while authentication or the call handler initializes. Handler registration requests replay of the original OS response; its original 30-second expiry still applies, including an expiry wakeup during auth loading. Calls never enter the durable retry queue. Warm-listener and cold-replay delivery share one in-flight operation, and only a consumed matching response is cleared. The call overlay fetches the recipient-bound ringing row even when no realtime signal exists in memory, then reuses `answerIncomingCall` for the conditional backend decision and account/terminal checks. Event actions likewise defer until their protected handler registers. Eighteen actual-source notification tests pass, including delayed auth/handler startup, recipient-bound hydration, confirmation-before-clear, duplicate-delivery sharing, call expiry while auth is loading, handler unmount during identity resolution and account switching during identity resolution; TypeScript passes (`/tmp/watch-notification-readiness-tests.log`, `/tmp/watch-notification-readiness-tsc.log`).

Apple conversation initial positioning now assigns the bound scroll position to the latest message rather than issuing an imperative scroll before the first layout. Existing saved-anchor positioning remains unchanged; native capture verification is recorded separately by the release agent.
