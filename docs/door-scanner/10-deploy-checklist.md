# 10 — Deploy checklist

Order is not negotiable: **`ticket-scan` → migration → web.** The function
tolerates the old schema; the web build does not tolerate the old function.

## Before

- [ ] `pnpm test` green (658)
- [ ] `pnpm --filter web typecheck` exits 0, and `tsc -p apps/mobile` exits 0
- [ ] `pnpm verify:routes` green
- [ ] E2E green against a **production build**, not dev
- [ ] `pnpm install --frozen-lockfile` clean — Vercel installs frozen

## 1. `ticket-scan`

- [ ] Deploy from this branch's source
- [ ] **Re-check `verify_jwt`.** A deploy resets it, and this function answers
      its own 401 — it must stay `false` or every scan fails
- [ ] Re-run the `04` harness: expect **22/22**
- [ ] Probe `/api/fn/ticket-scan` on **both** `dvntapp.live` and
      `www.dvntapp.live`

## 2. Migration `20260918000000_going_survives_check_in.sql`

- [ ] Apply
- [ ] Confirm the going count on a test event reads **60 → 60** across a scan,
      not 60 → 0
- [ ] The down migration is written and stays **unapplied**. Forward-safe: it
      widens a predicate

## 3. Web

- [ ] Deploy
- [ ] **Confirm `/vendor/zxing/3.1.0/zxing_reader.wasm` is served 200 in
      production.** It is git-ignored and generated by the `apps/web`
      postinstall; Vercel's installCommand is `pnpm install`, which runs it —
      but the postinstall chain ends in `|| true`, so a failure is silent and
      degrades to the jsDelivr CDN. That is the one thing a bad-signal door
      cannot afford
- [ ] Load the scanner on a phone over HTTPS and confirm the camera starts.
      **Plain LAN http is not a secure context and `getUserMedia` is blocked**
- [ ] Confirm `?engine=legacy` loads the legacy scanner

## Rollback

| Layer | How |
|---|---|
| Web | Vercel instant rollback |
| `ticket-scan` | redeploy from `27cd9a5` |
| Migration | forward-safe; leave applied |

## Native

Patch 01's verdict changes reach native **only** through a new build or OTA.
State plainly in the PR whether that ships before Saturday — if it does not,
the native scanner keeps the old verdict behaviour while web has the new one.

## Do not deploy

`02-after-saturday-web-session-fix.patch` and
`03-after-saturday-www-redirect.patch`. Both can sign a guest out while they
are pulling up a ticket in line.
