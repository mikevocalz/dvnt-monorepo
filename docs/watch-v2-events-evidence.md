## Now and venue weather enrichment

Now falls back to the nearest active event relationship when there is no upcoming ticket, including invitations without a ticket. The CTA opens the same current EventStore detail and displays event snapshot freshness.

Venue weather uses the existing Live Surface API, solely with coordinates already present in an authorized event row. No watch/phone location lookup is added. A memory-only generation-scoped cache permits one focused venue request in 15 minutes, including concurrent loads and changed focus. Optional weather never delays the event snapshot beyond an eight-second response budget; failed/unavailable weather is omitted. The existing API accepts an optional caller scope callback checked after its token await and before HTTP. Results recheck the current account. Native detail labels Fahrenheit and the actual API generated timestamp rather than presenting it as forecast weather at the future event time. Wear consumes the same optional fields.

`node --import tsx --test packages/app/features/watch/watch-event-weather.test.ts`: 3/3 passed for concurrent/rate-bound requests, no request without eligible published coordinates, and account-change suppression. Standalone Swift Events checks still pass after adding the optional weather model. Physical map/weather display remains acceptance work.

## Published Event moments preview

A deeper schema audit found an existing authorized photo source under a different product name: `apps/mobile/supabase/migrations/20260502_event_moments.sql` permits SELECT only for unexpired, non-flagged published moments; `create-event-moment/index.ts` accepts uploads only from the host, accepted co-organizer or ticket holder. The existing native phone consumer is `packages/app/features/events/ui/WhoAllOverThere.tsx:fetchMoments`. This is an ephemeral publication (event end + twenty-four hours), not a persistent/private album.

The watch now uses that explicit audience contract to show **Event moments**, at most six photos. A live event action reads the existing table and both directions of the member's `blocks` relationship. Block read failure, media read failure, generation change, missing date, video, flag, expiry and unsafe URL fail closed. Only the currently requested event receives photo URLs in its bounded snapshot. No author names, public attendee counts or inferred Crew identities are attached. Swift and Wear use the existing bounded image cache and provide an enlarged view. Both the thumbnail list and an already-open viewer stop displaying at the earlier of the original moment expiry and a five-minute permission lease; reconnecting refreshes visibility rather than allowing indefinite offline permission assumptions.

`watch-event-moments.test.ts` passes three actual projection tests covering the six-image/rendition limit, block/flag/media/date/URL exclusion, original expiry precedence and dedupe. `WatchEventMomentTest.kt` adds native cutoff and malformed-date tests. TypeScript check `/tmp/watch-moments-tsc.log` passes. Consolidated native compiles are owned by the main native verification tasks.

Additional concrete Crew/chat audit: `20260615135644_get_event_attendee_avatars.sql` is a security-definer RPC granted to anon/authenticated that returns the latest five RSVP avatars/initials without reciprocal relationship or per-event disclosure consent. `20260904140100_event_list_rpcs_video_flyer.sql` computes `friends_going` from a one-direction `follows` join and aggregate count. Neither satisfies mutually permitted named Crew disclosure, so neither is used. `20260810190000_event_perks_and_presence.sql` explicitly revokes client access to `event_presence`, with host-only aggregate/roster reads; a user's consent to share arrival with a host is not consent to reveal it to Crew. `messages-impl.ts:createGroupConversation` accepts arbitrary participant IDs and a group name, while `create-conversation/index.ts` accepts only another user/auth ID; neither accepts an event identity or defines event membership. Creating or renaming a generic group on a member's behalf would invent the missing event-chat association/consent. Permissioned Crew and event-chat remain a concrete schema/API dependency.
