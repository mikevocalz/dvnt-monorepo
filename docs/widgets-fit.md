# DVNT Home-Screen Widgets & Live Activities — Fit (PROMPT 15)

> Built on the **stable `expo-widgets`** library (SDK 56): iOS home-screen
> widgets + Live Activities authored as **`@expo/ui` (SwiftUI) layouts** with a
> timeline API — **no hand-written WidgetKit / Swift**. Anchored to
> `docs/dvnt-design-system.md` (after-dark, glass, teal-blue + purple).
> Written 2026-09-25.

## TL;DR

- The old, **disabled** hand-written WidgetKit + ActivityKit path was removed and
  replaced by `expo-widgets`. Live Activities are **all-new** on
  `createLiveActivity`, not a migration of the old Swift.
- Three pillars, three widgets: **Tickets**, **Blog**, **Social** — each with
  small / medium / large families (tickets also ships Lock Screen accessory
  families). Carousels are **timeline-driven** (entries advance on a schedule).
- **Content safety is enforced at the App-Group WRITE layer**: the app builds a
  **safe-only** dataset (spicy / NSFW / age-gated filtered out) and only that is
  written to the shared store. A spicy-only ticket set shows a **neutral branded
  state**; a spicy event's Live Activity uses a **neutral title**. Proven by
  `packages/app/lib/widgets/__tests__/safety.test.ts`.

## 3. Carousels, logo & motion (within widget constraints)

- **Carousels = timeline API.** The app writes a series of `WidgetTimelineEntry`
  `{ date, props }` where each entry advances the shown item (ticket→ticket,
  post→post). WidgetKit rotates through them on schedule, so the widget visibly
  cycles without needing interactivity.
- **Live countdown** uses `@expo/ui` `Text({ timerInterval, countsDown })` — a
  SwiftUI live timer (motion within constraints, no polling).
- **Progress ring** ("time to doors") uses `Gauge` / `ProgressView`.
- **Glass** uses the `glassEffect` modifier + `GlassEffectContainer`; near-black
  surfaces, hairline `white/10`, the gradient wordmark (large) / glyph (small).
- **Light/dark:** the widget reads `environment.colorScheme`; brand colors are
  explicit so they never invert to mush.

## 4. Data flow

```
app (safe sources) ──► buildWidgetDataset (spicy filtered) ──► WidgetBackend.write
  packages/app/lib/widgets                                     apps/mobile/widgets/backend.ts
                                                                  │
                                                                  ├─ cache images → widgetsDirectory (App Group)
                                                                  └─ widget.updateTimeline([...entries])  ──► WidgetKit reads timeline
```

- **Shared, native-free core** (`packages/app/lib/widgets`): `types.ts`,
  `safety.ts`, `dataset.ts`, `sync.ts`, `live-activity.ts`. Pure and testable;
  no `expo-widgets` import (so it's web/Android-safe).
- **Native backend** (`apps/mobile/widgets/backend.ts`) registers itself via
  `registerWidgetBackend` / `registerLiveActivityBackend` at boot
  (`apps/mobile/widgets/index.ts`, imported from the app entry). It holds the
  `createWidget` instances and turns the safe dataset into per-widget timelines.
- **When we sync:** on boot and on the events that change the data — new ticket,
  new blog post, activity/unread change, tier change. Driven by
  `useWidgetSync()` mounted in the protected layout; reuses existing prefetch.
- **Live Activity:** `live-surface` (`use-live-surface.ts`) already fetches the
  event payload; its iOS bridge now maps that to a **safe** Live Activity state
  and calls the injected LA backend (`createLiveActivity`). Host broadcasts
  (Prompt 7B) update the running activity; the door countdown is a live timer.

## 6. Content safety — SAFE-ONLY, ALWAYS (hard rule)

Widgets are a public, App-Store-reviewed surface. **No spicy / NSFW / age-gated
content ever reaches a widget or Live Activity**, and the guarantee is enforced
at the **data/write layer**, not the UI:

- `safety.ts#isWidgetSafe` is the single predicate. It rejects any
  `nsfw` / `is_nsfw` / `isNSFW` / `spicy` flag and any non-public `visibility`
  (`spicy`, `mature`, `age_gated`, `private`, `followers`, `close_friends`, …),
  mirroring the strict spicy contract in `lib/api/posts.ts`.
- `buildWidgetDataset` / `buildEventLiveActivityState` apply it **before** the
  App-Group write, so unsafe items are never serialized into the shared store —
  they can't leak via a stale timeline or a debugger.
- **Neutral fallbacks:** if a user's only upcoming ticket is spicy,
  `ticketsSuppressed` is set and the widget shows *"You've got plans 👀 — open
  DVNT"* (DVNT wordmark, no event name/flyer). A spicy event's Live Activity
  renders *"Your event starts soon"* with no spicy naming/art.
- **Test:** `__tests__/safety.test.ts` asserts spicy tickets/posts/activity never
  appear in the dataset, that the serialized payload contains none of the spicy
  strings, and that the neutral state / neutral Live Activity trigger correctly.

## 7. Boundaries & follow-ups

- **iOS only** via `expo-widgets`. Android home widgets are a **separate effort**
  (the plugin supports them behind `enableAndroid`, intentionally left off here).
  Android keeps its existing foreground live-notification.
- **Own data only** — nothing surfaces another user's private content.
- **Device verification required:** widgets render only on a real device /
  simulator. Remaining on-device checks: `expo prebuild` clean; each family
  renders with the carousel cycling + tier badges + countdown; blog carousel
  cycles; social glance; brand crisp on light + dark home screens; deep links
  land; Live Activity counts down and reflects a host broadcast; the
  content-safety behavior holds end-to-end.
