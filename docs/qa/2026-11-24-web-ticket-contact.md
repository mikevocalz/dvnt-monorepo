# Web ticket contact staged rollout

- Scope: web/mobile-web guest paid/free tier checkout, paid third-party embed, verified guest free RSVP and authenticated member ticket/cart/RSVP. Older native callers have no v1 marker or browser Origin; comp/invitation/door rails and old tickets are unchanged. Ticket username is a normalized guest-provided lookup label, never an account identity or reservation. Canonical signed-in username and email come from the verified account. Only the signed-in caller can fill their previously empty private phone.
- Private guest tables: one immutable contact per exact purchase order; one contact per originally issued guest ticket. The private copy requires exact order/event/current guest email and paid Checkout session; atomic free wrappers bind rows in the same database transaction. Claim, transfer, or order/guest-email reassignment erases the ticket copy and later updates cannot recreate it. Search/exports must additionally check current owner null, matching ticket/order/email, and staff authorization. Keep phone/username out of Stripe metadata and public payloads.
- Staged rollout: apply SQL before dependent Edge routes; leave DVNT_REQUIRE_WEB_TICKET_CONTACT unset/false initially so cached old pages and installed native keep working. New guest checkout, guest RSVP and embed verify a non-writing capability and private schema before sending finalization or email code. Signed-in web browsers probe the exact Edge function without event/tier/cart identity before any purchase call; old runtimes cannot issue from the probe. Explicit v1 is always enforced. V1 mutation bodies nest all purchase identifiers so a split or rolled-back old Edge cannot act even after a successful new-version probe; the browser requires a v1 acknowledgment before showing payment, redirect, or issuance success. When all Checkout Edge functions and browser surfaces are verified together and prior cached web compatibility checked, separately approve setting DVNT_REQUIRE_WEB_TICKET_CONTACT=true so an old web body cannot omit the fields. No native release is needed. Test old pages, latest pages, old native and embedded checkout resume before activation. Roll back enforcement first (unset/false); do not deploy an old Edge behind an active v1 browser, which intentionally stops rather than buying against a backend that ignores the contact. Keep additive SQL on rollback.
- Test synthetic paid/free checkout, exact order/session/email binding, normalized fields, absence of public phone and provider metadata, same-key replay, atomic rollback, owner change, and legacy/activation cases. Do not use real tickets, send live codes or execute live payments.
